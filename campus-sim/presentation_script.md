## 3. 슬라이드별 대본

### 1. 표지 [0:00–0:30]
「안녕하세요, [학번] [이름]입니다. 제가 이번 학기에 만든 시스템은 **캠퍼스 랩**입니다. 이름 그대로 내 학기를 미리 실험해 보는 곳입니다. 학기 초에 인턴을 병행할지, 학점에 집중할지, 동아리를 늘릴지 고민될 때, 선택지마다 남는 자유 시간과 예상 학점을 같은 기준으로 비교해 주는 학기 시뮬레이터입니다. 오른쪽이 실제 결과 화면입니다. 지금부터 발표 양식의 열두 가지 항목 순서대로 소개하겠습니다.」

### 2. 개발 목적 [0:30–1:30]
「학기 초가 되면 많은 학생이 인턴을 할지, 학점에 집중할지, 동아리를 더 할지 고민하는데, 대부분 감으로 정합니다. 저는 이 고민을 세 가지 문제로 정리했습니다. 첫째, 선택지를 같은 기준으로 비교하기 어렵다. 둘째, 시간이 모자란다는 걸 학기 중간에야 안다. 셋째, 지난 학기 경험이 다음 계획에 쌓이지 않는다. 그래서 같은 칸으로 나란히 비교하는 비교표, 시간이 넘치면 미리 띄우는 경고, 학기 말 기록으로 다음 예측을 보정하는 기능을 만들었습니다. 시간표 앱이나 학점 계산기는 이미 있지만, '이 시간 배분이면 학점이 어떻게 될까'를 미리 비교하는 도구는 제가 찾아본 범위에서는 찾기 어려웠기 때문에 이 시스템이 필요하다고 판단했습니다.」

### 3. 사용자와 사용 장면 [1:30–2:20]
「예를 들어 3학년 민지가 인턴 제안을 받았는데, 장학금 기준 3.9를 지키면서 할 수 있을지 고민한다고 해 보겠습니다. 학기 초에는 5분 정도 씁니다. 네 칸을 넣고 인턴 15시간, 학점 집중 5시간, 동아리 10시간을 넣으면 예상 학점이 나란히 나오고, 목표 3.9를 넣으면 '인턴은 주 5시간까지'라고 거꾸로 계산해 줍니다. 학기 중에는 실제로 쓰는 시간이 달라졌을 때 중간 점검이나 상담을 쓰고, 학기 말에는 실제 학점과 후기를 1분 정도 기록하면 다음 학기 예측이 나에게 맞춰집니다. 설치나 가입 없이 브라우저에서 링크만 열면 됩니다.」

### 4. 시스템 구성 ① 구조도 [2:20–3:20]
「구조는 세 층입니다. 화면 층에는 소개 페이지, 브라우저에서 바로 실행되는 웹 앱, 내 컴퓨터에서 실행하는 로컬 앱이 있습니다. 가운데 모듈 층에서 profile이 입력을 검증하고, scenario가 선택지를 정리해 저장하고, simulation이 예상 학점을 계산하고, compare가 비교하며 시간 부족을 경고하고, report가 보고서를 씁니다. 그리고 feedback이 학기 말 결과를 다음 학기 simulation으로 되돌려 주는 순환 구조가 핵심입니다. 상담은 counsel 모듈이 맡습니다. 아래 데이터 층은 CSV 파일 하나와, 내 컴퓨터에서 API 키가 있을 때만 쓰는 Claude API입니다.」

### 5. 시스템 구성 ② 도구 · 화면 흐름 [3:20–4:00]
「언어는 Python, 화면은 Streamlit을 썼고, stlite로 이 앱을 서버 없이 브라우저 안에서 실행해 GitHub Pages에 무료로 배포했습니다. AI 서비스는 Anthropic Claude API의 claude-opus-5-5 모델입니다. 테스트는 unittest와 화면 자동 시험 도구 Playwright로 했고, 개발 과정에서 AI 코딩 도구 Claude Code의 도움을 받았습니다. 화면은 홈부터 기록 관리까지 메뉴 아홉 개로 이어집니다.」

### 6. 알고리즘 ① 입력 → 처리 → 출력 [4:00–5:00]
「예상 학점의 뼈대는 계산식입니다. 자유 시간의 60%는 남아야 학점이 유지된다고 가정하고, 인턴 같은 공부 외 활동은 그 여유를 깎아 학점을 내리고, 공부 시간은 학점을 올립니다. 수강 학점이 18학점보다 많으면 조금 내립니다. 그래서 인턴 15시간 3.70, 학점 집중 5시간 4.05, 동아리 10시간 3.80이 나옵니다. 계산식을 고른 이유는 같은 입력이면 항상 같은 값이 나오고, 계산 근거로 왜 그 숫자인지 설명할 수 있어서입니다. 다만 0.6, 0.02 같은 기준값은 검증 전 가정이라는 점을 분명히 말씀드립니다.」

### 7. 알고리즘 ② 3단계 보정과 AI 모델 [5:00–6:10]
「예상 학점은 세 단계로 만들어집니다. 1단계 계산식, 2단계 내 기록 보정입니다. 지난 학기 오차를 기록 수 n에 대해 n/(n+2)만큼만 반영해서, 기록이 한 건이면 3분의 1만 반영합니다. 3단계는 AI 보정입니다. '주 3일 근무' 같은 글 조건을 Claude Opus 5.5에 보내 ±0.3 안에서만 보정하고, JSON 형식으로만 받으며, 범위를 넘거나 실패하면 계산식 결과를 그대로 씁니다. AI가 숫자를 직접 정하지 않게 한 이유는 같은 질문에도 답이 달라질 수 있어 설명하기 어렵기 때문입니다. 상담은 키가 있으면 Claude가, 웹에서는 14개 주제 분류와 질문 속 시간 계산을 하는 규칙 기반으로 답합니다.」

### 8. 데이터 [6:10–7:00]
「외부 데이터셋 없이 사용자가 입력한 값만 씁니다. simulation_log.csv 한 파일, 한 줄은 한 학기의 한 선택지, 항목은 10개로 고정했습니다. 저장 전에 범위를 검사하고, 활동이 여러 개면 '인턴 병행(15) + 공부(5)'처럼 한 칸에 적어 칸을 늘리지 않았습니다. 예상 학점은 저장하지 않고 매번 다시 계산합니다. 학번 · 이름 · 소득은 받지 않고, 웹 기록은 내 브라우저에만 저장되며, AI에는 숫자와 선택지 글만 보냅니다. 글꼴과 라이브러리는 공개 라이선스만 썼습니다.」

### 9. 주요 기능 [7:00–7:40]
「핵심 기능은 네 가지입니다. 선택지 비교, 목표 학점 역산, 질문 속 시간으로 바로 계산하는 상담, 그리고 실제 결과를 남기면 다음 예측에 반영되는 학기 말 기록입니다. 그 밖에 보고서 내려받기, 학기 중 점검, 기록 백업이 있습니다. 이제 직접 보여 드리겠습니다.」

### 10. 데모 [7:40–10:40, 3분]
> 슬라이드에서 미리 열어 둔 브라우저 탭으로 전환

1. **소개 페이지**: 「슬라이더로 인턴 시간을 30시간까지 올리면 시간이 모자라는 선택지에 바로 경고가 뜹니다.」
2. **앱 탭으로 전환**(미리 로딩해 둔 탭) → ▶ 시작하기
3. **프로필**: 2026-2 · 3.8 · 18 · 25 → 저장
4. **선택지**: 인턴 병행 15 · 학점 집중 5 · 동아리 확대 10 → 📊 저장하고 비교하기
   「학점 집중 4.05, 동아리 3.80, 인턴 3.70이 나옵니다.」
5. **🎯 목표** 탭 → 3.90 입력 「인턴은 주 5시간까지 괜찮다고 거꾸로 계산해 줍니다.」

> **문제가 생기면**: 「인터넷 상태 때문에 미리 녹화한 1분 37초 영상으로 보여 드리겠습니다.」 → `demo.mp4` 재생

### 11. 결과와 검증 ① [10:40–11:30]
「단위 테스트 55개가 모두 통과하고, 약 25단계의 전체 화면 회귀 시험을 Streamlit 두 버전과 공개 웹, 세 환경에서 통과했습니다. 무작위 입력 1만여 개에서도 오류는 0건이었습니다. 계산부터 보고서까지 한 번에 0.05밀리초, 웹 앱 첫 실행은 9~11초입니다. 정확도는 실제 학기 데이터가 아직 없어 측정 전이고, 학기 말 기록이 쌓이면 예측 오차의 평균 절댓값으로 바로 확인하도록 만들어 두었습니다.」

### 12. 결과와 검증 ② [11:30–12:20]
「받은 지적을 숫자로 고쳤습니다. 첫째, 첫 버전은 공부 시간도 투입 시간으로 보고 학점을 깎아서 학점 집중이 3.90이었는데, 고친 뒤 4.05가 됐습니다. 둘째, 교수님께서 글이 많아 읽기 어렵다고 지적해 주셔서 결과와 보고서를 나누고 안내를 접었고, 휴대폰 기준 소개 페이지 길이가 절반으로 줄었습니다. 셋째, 상담 답이 비슷하다는 반응에 주제 분류를 넣어 질문 21개에 모두 다른 답을 하게 됐습니다.」

### 13. 상용성 [12:20–13:10]
「에브리타임은 시간표로 '언제'를, 학점 앱은 성적으로 '결과'를 다루지만, 캠퍼스 랩은 시간 배분이 학점에 줄 영향을 미리 비교하고 기록할수록 나에게 맞춰집니다. 예상 사용자는 2025년 고등교육기관 재적 학생 약 301만 명입니다. 호스팅은 무료이고 AI는 한 번에 약 3~5센트로 추정합니다. 기본은 무료, AI 상담은 구독이나 대학 학생지원센터 기관 이용권으로 수익을 내고, 학교 시간표 · 졸업 요건 연동으로 확장할 수 있습니다.」

### 14. 수업 내용 적용 ① 주차별 표 [13:10–13:50] ★
「이제 이 발표에서 가장 중요한 부분, 수업 내용을 어떻게 적용했고 시스템이 어떻게 발전했는지입니다. [채운 주차부터 차례로: "○주차에 ○○를 배워서, 우리 시스템의 ○○에 이렇게 적용했습니다. 화면/코드의 ○○에서 확인할 수 있습니다."] 9주차 목적 정의서에서는 대학생의 시간 배분 고민을 문제 1~3으로 정의하고 기능마다 F01~F12 번호를 붙였는데, 이 번호는 지금도 코드 주석에 그대로 남아 있습니다. 저장 항목 10개도 이때 정했고, 기능을 늘리면서도 이 10칸은 늘리지 않았습니다. 10주차 확정 모듈 구성표에서는 6개 모듈로 나누고 모듈마다 완성 확인 방법을 정해, 그대로 테스트 코드 19개로 만들었고 지금은 55개입니다. 이 두 주차의 문서가 설계도가 되었습니다.」

### 15. 발전 과정 ② 타임라인 [13:50–14:40] ★

## 4. 예상 질문과 답변

**Q1. 계산식의 0.6, 0.02는 어떻게 정했나요?**
「결과가 상식적인 범위에서 움직이도록 정한 가정이고, 실제 데이터로 검증한 값은 아닙니다. 그래서 화면에 '검증 전 가정'이라고 표시했고, 학기 말 기록의 오차로 내 기록 보정이 줄여 가도록 했습니다. 기록이 쌓이면 회귀 분석으로 다시 정하는 게 다음 과제입니다.」

**Q2. AI가 틀린 값을 주면요?**
「세 겹으로 막았습니다. JSON 형식이 아니면 버리고, ±0.3을 넘으면 그 선택지는 보정하지 않고, 실패하면 계산식 결과만 보여 주며 'AI 보정 없음'과 이유를 표시합니다.」

**Q3. 왜 AI가 직접 학점을 예측하지 않나요?**
「같은 질문에도 답이 달라질 수 있고 이유를 설명하기 어렵기 때문입니다. 숫자의 뼈대는 항상 같은 값이 나오는 계산식이, AI는 계산식이 못 읽는 글만 맡도록 역할을 나눴습니다.」

**Q4. 웹에서는 왜 AI가 안 되나요?**
「공개 웹페이지에 API 키를 넣으면 누구나 볼 수 있어서입니다. 키를 숨기는 서버를 두는 것이 개선 계획에 있습니다.」

**Q5. 정확도는 얼마인가요?**
「실제 학기 결과 데이터가 아직 없어서 측정하지 못했습니다. 대신 학기 말 기록을 남기면 예측 오차를 바로 계산하고, 평균 절댓값으로 정확도를 확인할 수 있게 만들었습니다.」

**Q6. 개인정보는요?**
「학번 · 이름 · 소득은 처음부터 받지 않고, 웹 기록은 내 브라우저에만 저장됩니다. AI에는 숫자와 선택지 글만 보냅니다.」

**Q7. AI 도구(Claude Code)를 쓰면 본인이 만든 건가요?**
「문제 정의, 기능 · 데이터 설계(9 · 10주차 문서), 첫 버전 코드는 제가 만들었고, 이후 개선 과정에서 AI 코딩 도구를 보조로 썼습니다. 어떤 기능을 넣고 무엇을 고칠지는 제가 정하고 확인했으며, 사용 사실은 참고자료에 밝혔습니다.」 *(실제 사용 범위에 맞게 고쳐 말하세요)*
