## 5. 핵심 코드 ② — 예상 학점 계산식 (`simulation.py`) (1분 30초) ★

**[화면]** 계산식 슬라이드 + `base_gpa` 함수

```
보정 전 예상 학점 = 현재 학점
                 + (자유 시간 − 공부 외 시간 − 자유 시간 × 0.6) × 0.02
                 + 공부 시간 × 0.01
                 − (수강 학점 − 18) × 0.01
```

```python
SPARE_RATIO = 0.6       # 자유 시간 중 이만큼은 남아야 학점이 유지된다고 가정
HOUR_WEIGHT = 0.02      # 남는 시간 1시간당 학점 변화
BASE_CREDITS = 18       # 기준 수강 학점
STUDY_WEIGHT = 0.01     # 공부 시간 1시간당 학점 변화

raw = gpa + (free - other - free * SPARE_RATIO) * HOUR_WEIGHT + study * STUDY_WEIGHT - credit_part
```

「이 프로젝트의 중심인 계산식입니다. 생각은 단순합니다.

**첫째**, 자유 시간 중 60%는 남아 있어야 학점이 유지된다고 가정합니다. 인턴이나 동아리 같은 **공부 외 활동**은 그 여유를 깎아서 학점을 내립니다.
**둘째**, **공부 시간**은 반대로 학점을 올립니다. 활동 이름에 '공부, 시험, 과제' 같은 단어가 들어가면 자동으로 공부로 판단하고, 사용자가 직접 체크해서 바꿀 수도 있습니다.
**셋째**, 수강 학점이 18학점보다 많으면 조금 내립니다.

예를 들어 현재 학점 3.8, 자유 시간 25시간일 때, 인턴을 주 15시간 하면 3.70, 공부를 주 5시간 하면 4.05가 나옵니다.

그리고 **솔직하게 말씀드리면, 0.6, 0.02 같은 기준값은 실제 데이터로 검증한 값이 아니라 제가 정한 가정입니다.** 그래서 코드에도 화면에도 '검증 전 가정'이라고 표시해 두었고, 이 한계를 보완하려고 다음 장의 **내 기록 보정**을 만들었습니다.」

## 6. 핵심 코드 ③ — 3단계 보정과 AI (`simulation.run`) (1분 30초) ★

**[화면]** `run` 함수

```python
def run(profile, scenarios, past_records=None, ask=None):
    """계산식 → 내 기록 보정 → AI 보정(±0.3) → 예상 범위"""
    correction = personal_correction(past_records)
    span = prediction_range(past_records, correction)
    rows = [calculate(profile, scenario, correction["value"]) for scenario in scenarios]
    try:
        answers = parse_ai(ask(build_ai_input(profile, rows, past_records)))
    except Exception as error:   # AI가 어떤 이유로 실패해도 계산식 결과는 보여 줍니다 (F12)
        ...
```

「예상 학점은 **3단계**로 만들어집니다.

**1단계 계산식** — 방금 본 식입니다. 같은 입력이면 항상 같은 값이 나옵니다.

**2단계 내 기록 보정** — 지난 학기에 "예상보다 실제가 0.2 낮았다"면 그 오차를 반영합니다. 단, 기록이 1건뿐이면 우연일 수 있으니 `기록 수 / (기록 수 + 2)`, 즉 1건이면 3분의 1만 반영하고, 기록이 쌓일수록 더 많이 반영합니다. 그리고 ±0.3을 넘지 않게 막았습니다.

**3단계 AI 보정** — 계산식은 '주 3일 근무' 같은 **글로 된 세부 조건**을 못 읽습니다. 그래서 이 글을 Claude AI에게 보내 ±0.3 안에서만 보정하게 했습니다.
AI에게는 숫자와 선택지 글만 JSON으로 보내고, 답도 정해진 JSON 형식으로만 받습니다. 만약 AI가 0.3을 넘는 값을 주면 **그 값을 버립니다**.

마지막으로 가장 신경 쓴 부분이 **F12, 실패 대비**입니다. API 키가 없거나 인터넷이 끊기거나 AI가 엉뚱한 답을 해도, `try-except`로 잡아서 **계산식 결과는 반드시 보여 줍니다.** AI는 덧붙이는 기능이지, 없으면 멈추는 기능이 아닙니다.」

## 11. 한계와 개선 방향 (40초)

「한계도 분명히 말씀드리겠습니다.

1. **계산식의 기준값은 검증되지 않은 가정입니다.** 실제 학생 데이터가 쌓이면 회귀 분석으로 값을 다시 정해야 합니다.
2. **웹 버전에서는 AI 보정과 AI 상담을 쓸 수 없습니다.** API 키를 공개 페이지에 넣으면 누구나 볼 수 있어서, 내 컴퓨터에서 실행할 때만 켜지도록 했습니다.
3. 기록이 **내 브라우저에만** 저장되어, 기기를 바꾸면 CSV로 옮겨야 합니다.

개선 방향은 데이터가 쌓였을 때 기준값을 다시 맞추는 것, 그리고 키를 숨길 수 있는 서버를 두어 웹에서도 AI를 쓰게 하는 것입니다.」

# 부록 C. 예상 질문과 답변

**Q1. 계산식의 0.6, 0.02는 어떻게 정했나요?**
「근거가 있는 값은 아니고, 결과가 상식적인 범위에서 움직이도록 정한 가정입니다. 그래서 '검증 전 가정'이라고 표시했고, 실제 결과와의 차이는 내 기록 보정이 줄여 가도록 설계했습니다. 데이터가 쌓이면 회귀 분석으로 다시 정하는 것이 다음 과제입니다.」

**Q2. AI가 틀린 값을 주면 어떻게 되나요?**
「세 겹으로 막았습니다. 정해진 JSON 형식이 아니면 버리고, ±0.3을 넘으면 그 선택지는 보정하지 않고, 아예 실패하면 계산식 결과만 보여 줍니다. 화면에는 'AI 보정 없음'과 그 이유가 표시됩니다.」

**Q3. 왜 AI가 직접 예상 학점을 계산하지 않나요?**
「AI 답은 같은 질문에도 매번 달라질 수 있고, 왜 그 숫자가 나왔는지 설명하기 어렵습니다. 그래서 숫자의 뼈대는 항상 같은 값이 나오는 계산식이 맡고, AI는 계산식이 못 읽는 '글'만 보고 작게 보정하도록 역할을 나눴습니다.」

**Q4. 개인정보는 어떻게 보호하나요?**
「학번, 이름, 소득은 처음부터 받지 않습니다. AI에도 숫자와 선택지 이름만 보냅니다. API 키와 개인 기록 파일은 .gitignore로 GitHub에 올라가지 않게 했고, 웹 버전의 기록은 내 브라우저에만 저장됩니다.」

**Q5. 예상 학점을 왜 저장하지 않나요?**
「저장된 입력으로 계산식을 다시 돌리면 같은 값이 나오기 때문입니다. 따로 저장하면 계산식이 바뀌었을 때 옛날 값과 새 값이 섞이는 문제가 생깁니다.」

**Q6. 데이터가 하나도 없는 첫 학기에도 쓸 수 있나요?**
「네. 계산식은 기록 없이도 동작하고, 내 기록 보정은 0, 예상 범위는 기본값 ±0.3으로 시작합니다. 기록이 쌓일수록 보정과 범위가 나에게 맞춰집니다.」

**Q7. 웹 버전과 내 컴퓨터 버전은 뭐가 다른가요?**
「코드는 같습니다. 다만 웹 버전은 API 키를 안전하게 숨길 수 없어서 AI 보정과 AI 상담이 꺼지고, 계산식 결과와 기본 상담만 동작합니다.」
